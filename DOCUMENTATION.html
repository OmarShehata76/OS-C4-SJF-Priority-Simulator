Project Overview

This project compares two CPU scheduling algorithms: SJF (Shortest Job First — Preemptive) and Priority Scheduling (Preemptive). Both algorithms are executed on the exact same workload to ensure a valid and fair comparison.

The goal is to analyze the difference between a scheduler that prioritizes the shortest remaining burst time and one that prioritizes process importance (priority value), and to evaluate how each affects waiting time, response time, and turnaround time.

2

Algorithm Descriptions

⚡ SJF — Shortest Job First (Preemptive)

  • Always selects the process with the shortest remaining burst time from the ready queue
  • Preemptive: if a new process arrives with a shorter remaining burst time than the currently running one, it is immediately preempted
  • Also known as SRTF (Shortest Remaining Time First)
  • Tie-breaking: equal remaining burst time → earlier arrival time wins; if still tied → alphabetical Process ID

🎯 Priority Scheduling (Preemptive)

  • Always selects the process with the highest priority (lowest priority number) from the ready queue
  • Priority rule: lower number = higher priority (1 = most important, 10 = least important)
  • Preemptive: if a new process arrives with a higher priority than the currently running one, it is immediately preempted
  • Tie-breaking: equal priority → earlier arrival time wins
3

Metrics Calculated

CT — Completion Time
time when process finishes
The exact time at which the process finishes its execution on the CPU
TAT — Turnaround Time
TAT = CT − Arrival Time
Total time from when the process arrived until it completed execution
WT — Waiting Time
WT = TAT − Burst Time
Total time the process spent waiting in the ready queue without executing
RT — Response Time
RT = First CPU Time − Arrival Time
Time from when the process arrived until it first received CPU execution
4

Implementation Rules

Priority Rule: A lower priority number means higher importance. Priority = 1 is the most important; Priority = 10 is the least important.
Preemption Rule: Both algorithms are preemptive. The running process is interrupted immediately when a more eligible process enters the ready queue.
Tie-Breaking Rule: When eligibility is equal, the process with the earlier arrival time is selected. If arrival times are also equal, selection is made alphabetically by Process ID.
Same Workload Rule: Both algorithms must run on the exact same set of processes. A comparison is invalid if different datasets are used.
5

Input Validation

The simulator validates all input before the simulation begins and rejects any invalid data with a clear error message.

❌Negative Arrival Time: rejected — must be ≥ 0
❌Zero or Negative Burst Time: rejected — must be ≥ 1
❌Priority Out of Range: rejected — must be between 1 and 10
❌Duplicate Process ID: rejected — each process must have a unique ID
❌Empty Fields: rejected — all fields are required
❌Non-numeric Values in Numeric Fields: rejected
✅Valid Input: unique PID, AT ≥ 0, BT ≥ 1, Priority 1–10

Scenario B — Conflict: High-Priority Long Job vs Low-Priority Short Job

Scenario B Reveals the fundamental trade-off between burst time and priority
Purpose: P1 has the highest priority (1) but the longest burst time (10). P2 has the lowest priority (5) but the shortest burst time (2). The two algorithms will make opposite scheduling decisions.

SJF Behavior

P1 starts at t=0. At t=1, P2 arrives (BT=2) which is less than P1's remaining time (9) — P1 is preempted immediately. Short processes P2, P4, P3 complete quickly before P1 resumes and finishes last.

Priority Behavior

P1 has priority=1 (highest). No process can preempt it. P1 runs uninterrupted from t=0 to t=10. Afterward, processes are served by priority: P5 (2), P4 (3), P3 (4), P2 (5) last.

Key Observation: SJF completes short-burst processes quickly regardless of priority. Priority ensures the most important process (P1) runs to completion without interruption. This is the core trade-off: efficiency (SJF) vs urgency (Priority).

Starvation Observation: P5 has the lowest priority (5) and the longest burst time (8). In Priority Scheduling, P5 must wait until all four high-priority processes (P1–P4) complete before receiving any CPU time. In a continuous real system where new high-priority processes keep arriving, P5 could be delayed indefinitely — this is called starvation. SJF also delays P5 here due to the shorter burst times of P1–P4, but for efficiency reasons rather than priority-based discrimination.

Conclusion & Recommendation

Final Conclusion

SJF (Preemptive) achieved better results in terms of average waiting time and average turnaround time across all tested scenarios. By always executing the shortest available job, SJF minimizes waiting time for short processes and delivers the highest overall efficiency.

Priority Scheduling ensures the most important processes are always served first regardless of length — essential in real-time and critical systems. However, it carries a significant risk of starvation for low-priority processes.

Main Trade-off: SJF optimizes overall efficiency (lower average WT and TAT), while Priority Scheduling optimizes urgency (guarantees service for critical processes). The right choice depends on system requirements.

Recommendation for the tested workload: SJF — it produced lower average waiting time and turnaround time, making it more efficient for general-purpose workloads where all processes carry equal importance.
